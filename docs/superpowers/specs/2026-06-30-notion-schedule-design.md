# 设计：Notion 日程/任务管理系统 +（pomodoro 执行回写）

> 状态：已评审通过（2026-06-30）。本文为 brainstorming 阶段产出的设计 spec。

## Context（为什么做这件事）

用户是科研工作者（微生物菌群、TOC/EEM/紫外测定等），目前在 Notion 里只有零散的
「任务事项」「每日总结与思考」页面，没有结构化的任务/待办管理。希望建立一套
**"规划在 Notion、执行在 pomodoro、回写自动化"** 的闭环：

- Notion 负责**规划**：收集想法/待办、用四象限分类、按天排期、统计回顾。
- 已有的 **decision-pomodoro** 负责**执行**：跑番茄、记录决策产出（不改其代码）。
- 一个**定时 agent（cc cron）** 当桥：每晚把 pomodoro 导出的 markdown 总结回写到
  Notion 对应任务，并把"超时未决断"的待办推送成提醒。

核心理念延续项目的"完成大于完美"——先用纯 Notion 能立刻跑起来的结构，自动化作为叠加层。

## 已确认的关键决策

1. **单一数据库 + 阶段字段**（不分两个库）。靠视图区分待办池/日程，避免重复录入。
2. **过期处理 = 视图标红 + 人工复盘**；并在 v1 叠加**提醒**（agent 驱动）。
3. **pomodoro 不改代码**；用 agent 读取其导出的 markdown，总结后写回 Notion。
4. **agent 定时自动跑**（每晚 cron）：回写番茄记录 + 检查过期待办建提醒。
5. **大任务拆解用父子任务自关联**（子步骤是独立记录、自带日期，可单独排期/跑番茄）。
6. **象限兼任优先级**（不加独立优先级字段）；**加「领域」多选标签**。

## 一、Notion 数据库设计（任务库）

单个数据库，画廊/表格/看板/日历多视图。Properties：

| 字段 | 类型 | 说明 |
|------|------|------|
| 名称 | Title | 任务名 |
| 阶段 | Status | 收件箱 → 已排期 → 进行中 → 完成（Status 类型自带分组，便于统计） |
| 象限 | Select | 紧急重要 / 重要不紧急 / 紧急不重要 / 不紧急不重要 |
| 领域 | Multi-select | 论文 / 实验 / 杂务 / 生活（可后续增删） |
| 日期 | Date | 排期到哪天；为空=仍在收件箱 |
| 创建时间 | Created time | 用于计算停留/过期 |
| 决断日 | Formula(date) | 创建时间 + 象限对应天数 |
| 是否超时 | Formula(checkbox) | 阶段=收件箱 且 今天>决断日 → 标红/提醒依据 |
| 已停留 | Formula(number) | 今天 − 创建时间（天） |
| 上级任务 / 子任务 | Relation(自身) | 任务拆解 |
| 番茄数 | Number | agent 回写 |
| 完成情况 | Select | agent 回写：✅达标 / ⚠️未达标 / ⏸️进行中 |
| 复盘笔记 | 页面正文 | agent 把番茄复盘追加进任务页面 |

### 公式（象限停留时长：紧急重要1天 / 紧急不重要2 / 重要不紧急3 / 都不7）

**决断日：**
```
dateAdd(prop("创建时间"),
  if(prop("象限") == "紧急重要", 1,
   if(prop("象限") == "紧急不重要", 2,
    if(prop("象限") == "重要不紧急", 3, 7))), "days")
```

**是否超时：**
```
and(prop("阶段") == "收件箱", now() > prop("决断日"))
```

**已停留：**
```
dateBetween(now(), prop("创建时间"), "days")
```

> Notion 限制：公式算出的"决断日"**不能触发 Notion 原生提醒推送**，因此提醒由
> agent 主动检查并外发（见第三节），不依赖 Notion 自身推送。

### 视图

1. **📥 待办池** — 阶段=收件箱；按象限分组；显示「已停留」。
2. **⚠️ 该决断了** — 是否超时=✓；红色高亮；每周复盘 + agent 提醒都读它。
3. **📅 今日** — 日期=今天 且 阶段≠完成；执行时只看这个。
4. **🗓️ 本周日程** — 日期∈本周；日历或看板（按天分列）视图，供每周规划。
5. **📊 回顾统计** — 阶段=完成；按 周/象限/领域 分组，统计番茄数与完成率。

## 二、每周/每天流程（仪式）

- **周日晚·规划**：扫「待办池」+「该决断了」→ 挑本周要做的，填日期、阶段改"已排期"
  → 大任务现场拆子任务、分配到具体某天。
- **每天·执行**：看「今日」视图 → 在 pomodoro 跑番茄 → 收工导出 markdown。
- **每晚·自动**：cron agent 同步回写 + 检查过期建提醒。
- **周末·复盘**：看「回顾统计」→ 未完成的滚到下周或丢回收件箱。

## 三、自动化 agent（cc cron，每晚一次）

不修改 pomodoro。agent 每晚做两件事：

**A. 回写番茄执行结果**
1. 扫描 markdown 导出（默认下载目录 `番茄钟-YYYY-MM-DD-*.md`，路径在实现时确认）。
2. 解析每轮 session：任务名、关联日程、各阶段产出、完成情况、延后想法。
3. 按**任务名/关联日程标题**模糊匹配到当天 Notion 任务。
4. 回写：番茄数、完成情况；把复盘笔记追加到任务页面正文。
5. 可选：在「每日总结与思考」生成一条当日小结。

**B. 过期待办提醒**
1. 查询「该决断了」视图（是否超时=✓ 且未提醒过）。
2. 对每条创建提醒。

> ⚠️ **实现依赖**：headless 的 cc agent 没有 pomodoro 浏览器侧的 Google OAuth token，
> 无法直接复用其日历写权限。两条可选路径：
> - **(默认/推荐) Hermes 推送**：agent 直接经已连接的 Hermes(Telegram 等) 发提醒消息——
>   零额外鉴权、即时可用，且比日历事件更可操作。
> - **真·Google 日历事件**：需为脚本单独配置 Google 服务账号 / OAuth refresh token。
>
> 首版先用 Hermes 推送顶上，日历事件作为紧随其后的增强（待用户最终拍板）。

## 四、构建步骤（分增量交付）

> 第1层「纯 Notion 配置」建好即可立刻使用；第2层「自动化 agent」随后叠加。

1. **建数据库与字段**：用 Notion MCP 建库、加上述 properties，配置三条公式。
2. **建视图**：建 5 个视图，设好筛选/分组/排版。
3. **种子数据 + 自测**：录几条真实待办（覆盖四象限），验证过期标红、排期流转、拆解关联。
4. **自动化 agent**：写 cron 调度的 cc 任务，实现 A/B 两段逻辑；先接 Hermes 推送。
5. **试运行一周**：跑一轮"规划→执行→回写→复盘"完整闭环，按手感微调。

涉及的现有资产（复用，勿改）：
- `decision-pomodoro/src/export.js` — markdown 导出格式（agent 解析依据）。
- `decision-pomodoro/src/calendar.js` — 若走真·日历方案，可参考其 GCal 调用方式。
- Hermes MCP（已连接）+ Notion MCP（已连接）+ `project-registry.json`。

## 五、验证方式（端到端）

1. **Notion 结构**：三种象限各录一条待办；调创建时间往前，确认「该决断了」按
   1/2/3/7 天规则正确标红。
2. **排期流转**：给待办填日期+改"已排期"，确认它从「待办池」消失、进「今日/本周」。
3. **拆解**：父任务拆 2 个子任务分到不同天，确认子任务各自出现在对应「今日」。
4. **回写**：pomodoro 跑一轮导出 markdown，触发 agent，确认番茄数/完成情况/复盘被更新。
5. **提醒**：构造一条超时待办，触发 agent，确认收到 Hermes（或日历）提醒。
6. **统计**：完成几条任务后看「回顾统计」，确认按周/象限/领域计数与番茄数正确。
